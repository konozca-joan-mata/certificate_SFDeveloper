User Interface

Lightning Web Components y UI

El estándar moderno de Salesforce para construir interfaces: LWC, Aura y Visualforce.

1. Lightning Web Components — Estructura

LWC está basado en estándares web nativos (Web Components, ES6+, Shadow DOM). No es un framework propietario, lo que lo hace más rápido y cercano al JavaScript moderno.

📁 Archivos de un componente LWC

Un componente se define en una carpeta con el mismo nombre y hasta 5 archivos:

ArchivoPropósitoObligatorio
componentName.htmlTemplate HTML (estructura visual). Debe tener <template> como raíz.✅
componentName.jsLógica JavaScript. Clase que extiende LightningElement.✅
componentName.js-meta.xmlConfiguración del componente (dónde puede usarse: App Builder, Flow, etc.).✅
componentName.cssEstilos con Shadow DOM (aislados del resto de la página).❌
componentName.svgIcono personalizado para el App Builder.❌

Ejemplo de componente completo

<!-- miComponente.html -->
<template>
    <lightning-card title="Cuenta">
        <p>Nombre: {nombreCuenta}</p>
        <lightning-button label="Guardar" onclick={handleGuardar}></lightning-button>
    </lightning-card>
</template>
// miComponente.js
import { LightningElement, api, track, wire } from 'lwc';
import getNombreCuenta from '@salesforce/apex/CuentaController.getNombre';

export default class MiComponente extends LightningElement {
    @api recordId;           // Propiedad pública (recibe del padre o del contexto)
    @track nombreCuenta;     // Reactivo (para objetos/arrays internos)

    @wire(getNombreCuenta, { accId: '$recordId' })
    wiredCuenta({ data, error }) {
        if (data) this.nombreCuenta = data;
    }

    handleGuardar() {
        // lógica al hacer click
    }
}

2. Decoradores LWC

DecoradorPropósitoDirección
@api Hace una propiedad o método públicos. Permite que el componente padre pase datos al hijo. Reactivo automáticamente. Padre → Hijo
@track Hace una propiedad reactiva cuando cambian propiedades internas de un objeto o array. Para primitivos no es necesario (ya son reactivos por defecto). Interno
@wire Conecta la propiedad a un servicio reactivo: una función Apex con @AuraEnabled(cacheable=true) o un wire adapter estándar (como getRecord). Salesforce → Componente
💡 Tip de Examen: Para usar @wire con Apex, el método Apex DEBE tener @AuraEnabled(cacheable=true). Si el método modifica datos (no es de solo lectura), no puede ser cacheable y debes llamarlo imperativa mente con callApexMethod().then(...).

3. Comunicación entre Componentes

⬇️ Padre a Hijo — @api

El padre pasa datos mediante atributos HTML en el template.

<!-- En el padre -->
<c-hijo-componente nombre="Acme" record-id={cuentaId}></c-hijo-componente>

// En el hijo
@api nombre;
@api recordId;

⬆️ Hijo a Padre — CustomEvent

El hijo dispara un evento personalizado; el padre lo escucha.

// En el hijo — dispara el evento
this.dispatchEvent(new CustomEvent('guardar', {
    detail: { nombreCuenta: this.nombre }
}));

<!-- En el padre — escucha el evento -->
<c-hijo-componente onguar dar={handleGuardar}></c-hijo-componente>

// En el padre — manejador
handleGuardar(event) {
    console.log(event.detail.nombreCuenta);
}

📡 Entre Componentes No Relacionados — Lightning Message Service (LMS)

Para comunicar componentes que no están en la misma jerarquía (ej: un componente en la barra lateral con uno en el área principal de la página).

  • Requiere un Message Channel (.messageChannel-meta.xml).
  • El emisor usa publish() y el receptor usa subscribe().
  • Funciona tanto entre LWC como entre LWC y Aura.

4. Ciclo de Vida de un Componente LWC

🔄 Hooks de ciclo de vida

HookCuándo se ejecutaUso típico
constructor()Al instanciar el componente. El DOM no existe aún.Inicializar variables. No acceder al DOM.
connectedCallback()Cuando el componente se inserta en el DOM.Cargar datos, añadir event listeners externos.
renderedCallback()Después de cada renderizado del componente.Manipular el DOM después de renderizar. Cuidado: puede ejecutarse múltiples veces.
disconnectedCallback()Cuando el componente se elimina del DOM.Limpiar event listeners para evitar memory leaks.

5. Visualforce y Aura Components (Legado)

📄 Visualforce

Tecnología de páginas web propietaria de Salesforce. Usa etiquetas <apex:...>.

  • Standard Controller: Lógica básica del objeto (save, edit, delete) sin código.
  • Controller Extension: Añade lógica a un controlador estándar sin reemplazarlo.
  • Custom Controller: Control total con Apex, sin usar el controlador estándar.
  • Cuándo usarlo: Para generar PDFs, páginas de inicio de sesión personalizadas, o formularios web externos.

⚡ Aura Components

Predecesor de LWC, más verboso. Aún presente en orgs antiguas.

  • Usa <aura:component> como raíz.
  • Los atributos se definen con <aura:attribute>.
  • Los eventos con <aura:registerEvent> y <aura:handler>.
  • LWC puede embeberse dentro de Aura pero no al revés (compatibilidad de sentido único).
💡 Tip de Examen: Para proyectos nuevos, Salesforce siempre recomienda LWC. Usa Visualforce solo si necesitas generar PDFs (renderAs="pdf") o para páginas heredadas. En el examen, si preguntan cuál usar en una app nueva, la respuesta es siempre LWC.
